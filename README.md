## 🏗️ Approach & Logic

### Design Philosophy — *Democratic Clarity*

> Every pixel earns its place. Minimal, trustworthy, data-rich, quietly beautiful.
> *The Hindu* newspaper, if it were designed by Apple.

Civic information should feel **premium, not bureaucratic.** Existing government platforms use generic blue, dense tables, and unreadable PDFs. EPEP uses deep forest green (neutral, unowned in civic space), editorial typography, and micro-interactions that make democracy feel alive.

### Core Architectural Rule — *It Must Never Break*

```
Every API call has 3 layers:

  Layer 1  →  Live external API          (most accurate)
  Layer 2  →  Official fallback API      (data.gov.in, cached)
  Layer 3  →  Bundled static JSON        (always present, works offline)

AI chat has 4 layers:

  Layer 1  →  Google Gemma 3 27B         (primary)
  Layer 2  →  Llama 4 Maverick           (fallback)
  Layer 3  →  DeepSeek R2               (fallback)
  Layer 4  →  Local Q&A JSON DB         (150+ entries, works offline)
```

**Result: every feature works without internet, without any API key, forever.**

### Why This Approach Wins

```
What other civic platforms do:         What EPEP does:
─────────────────────────────────────  ──────────────────────────────────
Display static text and PDFs           Interactive simulation of EVM voting
Require stable internet                Works fully offline via PWA + SW
Break when one API goes down           4-layer fallback on every data call
Generic government design              Editorial design system
No mobile optimisation                 Mobile-first, 375px pixel-perfect
No AI assistance                       Multi-model AI with strict guardrails
Historical data: none or sparse        TCPD data from 1951 to 2024
Local/Vercel deployment                Google Cloud Run deployment
```

```
Map tiles (OpenStreetMap)       Stale-while-revalidate · 500 tiles
API data (TCPD, data.gov.in)    Network-first · 5s timeout · 7d cache
OpenRouter AI                   Network-only (never cache AI responses)

Fully offline:
──────────────────────────────────────────────────────────────
✅  Education Hub       all 150+ Q&As
✅  Quiz                all 80+ questions
✅  EVM Simulator       complete voting flow
✅  India Map           last cached state + boundaries
✅  Dashboard           18-election static dataset
✅  AI Chat             local Q&A database responds instantly
```

## 🔁 Fallback Architecture

```
SCENARIO                         USER EXPERIENCE
───────────────────────────────  ──────────────────────────────────────────
API call fails                   Warm error card · retry · "cached data" badge
No internet                      Offline banner · all features continue
AI rate limited                  Nothing — model rotates silently
All 3 AI models fail             Local Q&A responds — user never aware
GeoJSON fetch fails              Simplified bundled map renders with notice
Map tiles fail                   Stamen tiles activate automatically
Wrong constituency entered       Fuzzy-match suggestion shown inline

Rule: users never hit a dead end. Every failure has a recovery path.
```

## 📋 Assumptions Made

```
1. JUDGES USE CHROME
   Lighthouse targets (90+) calibrated for Chrome's rendering engine.

2. DEMO BUILD
   VITE_ API key is client-side — acceptable for competition context.
   Production would proxy AI calls through a backend service.

3. GEOJSON IS PRE-2026
   Datameet boundaries reflect pre-delimitation constituencies.
   Post-2026 updates are noted in the roadmap.

4. HISTORICAL DATA
   TCPD Lok Dhaba data is used as provided by Ashoka University.
   EPEP does not independently verify historical results.

5. AI ACCURACY
   AI constrained to factual answers with source citations.
   Responses should be independently verified at eci.gov.in
   for any legal or official purpose.

6. OPENROUTER FREE TIER
   Built for free tier rate limits. Heavy concurrent usage →
   rate limited → local Q&A fallback handles transparently.
```
